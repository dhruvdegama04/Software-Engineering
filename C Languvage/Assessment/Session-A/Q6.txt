Why the Program Crashes on an Empty String Input
An empty string in C/C++ consists of just a null terminator ('\0') stored at the first memory location. A crash (typically a Segmentation Fault or Access Violation) usually occurs when:

Unchecked Access: The program assumes a non-zero length and immediately attempts to access or dereference memory past the boundary, or

Null Pointer Dereference: The input pointer itself is NULL (uninitialized/invalid) and the code attempts to read its value (e.g., *ptr).

The Pointer Check Required Before Dereferencing
To ensure safety when using pointers, your function must perform a two-part defensive check before attempting any dereference operation (*ptr):
**-- C --**
// Safety check before dereferencing or processing
if (str == NULL || *str == '\0') {
    // Handle empty or invalid string safely (e.g., return 0, NULL, or error code)
    return;
}

Null Check (str == NULL): Verifies that the pointer actually points to a valid memory address.

Empty String Check (*str == '\0'): Checks if the first character at that address is the null terminator, signifying an empty string ("").

Which Approach Makes the Empty-Input Bug Easier to Catch?
Array index notation (str[i]) makes the empty-input bug easier to catch and prevent.

Reasons:
Self-Guarding Loop Condition: A standard index loop evaluates str[0] != '\0' immediately before executing the loop body:
**-- C --**
for (int i = 0; str[i] != '\0'; i++) {
    // Loop body never executes if str is "" because str[0] is '\0'
}
Explicit Base Reference: Index notation forces developers to keep the base variable str static, making it visually clearer when checking boundary constraints or NULL checks upfront before indexing into index 0.

Pointer Overstepping: With pointer arithmetic, developers often write loops like do { ... } while (*ptr++) or increment pointers prematurely before checking for \0, making it easier to dereference out-of-bounds memory on empty input.
